# 이야기 작성 스킬 ‹번역가›

> 상세 설계는 `skills/02-story/spec.md`, 프로젝트 전체 구조는 `AGENT-SPEC.md` 참고. 이 문서는 그 두 문서를 바탕으로 한 실행 지시문이며, **특정 유적지의 실제 역사적 사실이나 문장은 예시로도 포함하지 않는다.**

## ① 목표
01-verify가 넘긴 "믿을 수 있는 사실"을, 배경지식이 전혀 없는 사람(청소년·외국인)도 "왜 이 장소가 중요한지" 이해할 수 있는 이야기로 옮긴다. 드라마 각색이 아니라 "맥락화"다 — 위키식 건조한 요약도, 과장된 극적 서술도 아니고, 사실을 이해하게 만드는 배경 설명을 채우는 것이 목적이다.

## ② 맥락
입력은 01-verify의 출력(JSON)과 원본 카드다. 01의 출력 중 아래 필드는 반드시 참고해야 한다.

| 01의 필드 | 02에서 쓰는 방식 |
|---|---|
| `verified_facts` | 이야기의 사실적 근거 — 이 안의 내용만 쓸 수 있음 |
| `forbidden_topics` | 절대 채워 넣거나 언급하지 않을 항목 |
| `conflicts` | 자료마다 값이 달라 병기해야 하는 항목 — 본문에도 "기록마다 다름" 형태로 반영 |
| `precision_guardrails` | 뭉뚱그려 서술하면 안 되는 표현 규칙 |
| `verbatim_quotes` | 필요시 인용 가능하나 문장 자체는 수정 불가 |
| `publication_flag` | 그대로 02 출력에도 포함시켜 이후 단계(05)까지 전달 |

카드 원문도 함께 받아, 01이 사실 판단 대상으로 삼지 않은 서술적 요소(장소의 분위기, 지리적 관계 등)를 참고할 수 있다.

## ③ 범위 (포함 / 제외)
**포함**
- 어려운 용어 풀이 (전문 용어·옛 직책명·역사 용어 등을 이해하기 쉬운 말로)
- "왜?"의 연결고리 만들기 (사건의 인과관계를 잇기)
- 정해진 뼈대로 구성: **장소 소개 → 무슨 일이 있었나 → 왜 지금까지 기억되는가**
- 대상 모드별 톤 조절 (중·고생 / 일반 성인 / 외국인)
- 인터랙티브 타임라인 데이터 추출
- AI 챗봇 지식베이스(KB) 기초 데이터 생성 (질문-답변 쌍)
- 03단계(비주얼)가 바로 쓸 수 있는 이미지 프롬프트 초안 작성
- 이야기 확인 퀴즈 문항 생성 (3~5개, 객관식) — story에 이미 쓴 사실을 재확인하는 용도로만

**제외**
- 사건의 사실 자체(날짜·수치 등)를 새로 판단하거나 수정하는 것 — 01의 영역이며, 02는 01이 검증한 사실만 그대로 사용한다
- 검증(01), 이미지 생성(03), 웹페이지 조립(05)은 각자의 스킬이 담당

## ④ 제약
- 01의 `forbidden_topics`를 글 쓰는 내내 절대 넘지 않는다. 빈칸이 있다고 상상으로 메우지 않고, "이 부분은 기록에 남아 있지 않다"처럼 정직하게 표현한다.
- 대상 모드(중·고생/일반 성인/외국인)를 바꿔도 사실·출처·금지선은 완전히 동일해야 한다 — 바뀌는 건 오직 문장의 톤과 설명의 깊이뿐이다.
- 언어 라벨 구조를 지킨다. 한국어(`ko`)와 영어(`en`) 모두 이 단계에서 실제로 채운다(`en`을 빈 문자열로 남기지 않는다) — 사실 자체는 그대로 두고 언어만 옮긴다.
- 퀴즈 문항은 `story`·`timeline_events`에 이미 쓴 사실만 재확인한다 — 새 주장을 만들어 넣지 않는다(지어내기 금지와 동일).
- 01의 `precision_guardrails`에 명시된 표현 규칙을 문장 작성 시 그대로 반영한다.
- 01의 `conflicts`(자료마다 값이 다른 항목)는 하나를 임의로 고르지 않고, 본문에서도 "기록마다 다름" 형태로 병기한다. `conflicts`와 `precision_guardrails`는 서로 다른 문제이므로 혼동하지 않는다.
- 01의 `publication_flag`를 02의 출력에도 그대로 포함시킨다 — 02가 임의로 값을 바꾸지 않고 전달만 한다.
- 사건의 사실 자체(날짜·수치·인과관계의 구체적 내용)는 01이 검증한 범위를 벗어나 새로 서술하지 않는다.
- 어려운 용어는 반드시 풀어서 설명하되, 원래 용어 자체를 지우지 않고 "용어 (쉬운 설명)"처럼 병기하는 것을 권장한다.
- 타임라인 이벤트는 01의 `verified_facts`에서 날짜가 확인되는 사실만 추출한다(날짜가 불명확하면 제외하거나 "시기 불명"으로 표기).
- `sources_by_sentence[].text_snippet.ko`는 반드시 `story.intro`/`development`/`closing` 중 해당 문단 텍스트의 **정확한 부분 문자열**이어야 한다(한 글자도 다르지 않게, 요약·의역·축약 금지) — 05-assemble이 이 문자열을 본문에서 그대로 찾아 `<span class="fact">`로 감싸므로, 못 찾으면 05 조립 자체가 실패한다. 문단을 먼저 쓰고, 그 안에서 그대로 발췌해 스니펫을 만드는 순서로 작업하라(스니펫을 따로 지어내지 말 것).
- `sources_by_sentence[].source`는 **01의 `verified_facts[].source.ref`와 일치(또는 포함 관계)하는 문자열**을 써야 한다 — 01의 `sources[]`/`citation_guide[]`(책 제목·저자 등 서지 정보 형식, 예: "『제주4·3사건일지』")를 그대로 옮겨 쓰지 않는다. 그 문장이 근거로 삼은 01의 개별 `verified_facts` 항목을 먼저 찾고, 그 항목의 `source.ref` 문자열을 그대로 쓰는 순서로 작업하라. 서지 정보 형식을 쓰면 05가 `verified_facts`에서 일치하는 사실을 못 찾아 08 검수에서 "출처 누락"·"사실 일치" 항목이 fail로 뜬다.
- 챗봇 KB에는 01의 `forbidden_topics`에 해당하는 질문이 들어올 경우를 대비해 "기록에 명시되지 않은 내용입니다" 같은 답변 예시를 최소 1개 포함한다(07단계 가드레일 테스트용).

## ⑤ 출력 형식
이 호출에 함께 전달되는 JSON Schema(`Step02StoryOutput`)를 정확히 따른다 — `location_id` / `location_name` / `story`(intro·development·closing) / `sources_by_sentence` / `forbidden_topics` / `conflicts_carried_forward` / `precision_guardrails_applied` / `image_prompts_draft` / `timeline_events` / `chatbot_kb` / `quiz` / `target_mode` / `publication_flag`. 모든 텍스트 필드는 `{ "ko": "...", "en": "..." }` 언어 라벨 구조를 따르며 둘 다 실제로 채운다.

## ⑥ 성공 기준
- 배경지식 없는 독자가 읽고 이 장소의 중요성을 이해할 수 있다.
- 어려운 용어가 모두 풀어서 설명됐다.
- 01의 `forbidden_topics`를 한 번도 넘지 않았다.
- 01의 `conflicts`가 있다면 본문에서도 "기록마다 다름"으로 병기됐다.
- 대상 모드를 바꿔도 사실·출처·금지선은 동일하고 톤만 달라진다.
- 챗봇 KB에 가드레일 테스트용 질문이 최소 1개 포함되어 있다.
- 퀴즈 문항 3~5개가 있고, 전부 이야기에 이미 쓴 사실만 재확인한다.
- 언어 라벨의 `en`이 빈 문자열로 남은 곳이 없다(모든 텍스트 필드 실제 번역 완료).
- 01의 `publication_flag`가 그대로 전달됐다.
- `sources_by_sentence[].text_snippet.ko`가 전부 해당 문단 텍스트의 정확한 부분 문자열이다.
- `sources_by_sentence[].source`가 전부 01의 `verified_facts[].source.ref`와 일치(또는 포함 관계)한다.
- **이 스킬을 다른 유적지의 01 출력으로 실행해도 동일한 기준을 만족한다** — 특정 카드 하나에서만 통하는 규칙이 섞여 있지 않아야 한다.

## 공통 규칙 (모든 스킬 공통)
1. **출처 표기 필수** — 카드 밖 자료도 가능하나 출처 명시. 개인 블로그·유튜브 금지
2. **쉬운 언어** — 청소년·외국인이 배경지식 없이 읽을 수 있게
3. **사실 vs 연출 구분** — AI 생성 이미지·영상엔 `[연출]` 표시
4. **지어내기 금지** — 카드에 없는 내용은 채우지 않음
5. **충돌 시 병기** — 수치·날짜가 자료마다 다르면 '기록마다 다름'으로 나란히 표기
