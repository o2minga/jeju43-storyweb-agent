# 자료 검증·정리 스킬 ‹문지기›

> 상세 설계는 `skills/01-verify/spec.md`, 프로젝트 전체 구조는 `AGENT-SPEC.md` 참고. 이 문서는 그 두 문서를 바탕으로 한 실행 지시문이며, **특정 유적지의 실제 역사적 사실이나 문장은 예시로도 포함하지 않는다.**

## ① 목표
입력된 유적지 카드(.md) 하나를 분석해, 이후 단계(02-story)가 이야기를 쓸 때 "믿고 써도 되는 사실"만 남기고 라벨을 붙인다. 어떤 유적지의 카드가 들어와도 동일한 규칙으로 동작해야 하며, 파이프라인 전체 신뢰성의 뿌리 역할을 한다.

## ② 맥락
카드는 섹션별로 구성되지만, 모든 섹션이 항상 존재한다는 보장은 없다 — 있는 섹션만 방어적으로 파싱하고, 없으면 건너뛴다. 출처는 3가지 형식(인라인 브래킷 〔출처: ...〕 / 표의 출처 컬럼 / "출처 원문" 섹션의 원문 인용) 중 하나 이상으로 등장하며, 이 스킬은 **카드 내용이 아니라 이 형식 자체**를 인식해서 파싱한다. `⚠ 주의`류 섹션(이름은 카드마다 "주의"/"금지사항"/"유의사항" 등으로 다를 수 있음)이 있다면 가장 먼저·가장 정확하게 처리한다.

## ③ 범위 (포함 / 제외)
**포함**
- 카드 섹션 유무 확인 → 있는 섹션만 항목별로 추출 (기본정보/사건 연표 표, 출처 원문, 안내판 원문 등)
- 각 사실에 출처가 붙어 있는지 확인 (인라인 브래킷 / 표 컬럼 / 원문 인용 세 형식 모두 인식)
- 자료 간 충돌 검사 → 병기 처리
- "정확히 단정할 수 없다"는 경고는 충돌과 구분해 정밀도 주의 항목으로 별도 분류
- 지어내기 금지 항목을 원문 그대로 목록화
- 카드 내용이 부족할 때만 추가 검색 수행 (충분하면 생략)
- 카드 전체에 걸리는 공개 제한이 있으면 문서 전체 메타데이터로 표시

**제외**
- 이야기 작성 (02-story 담당) — "이야기 소재" 같은 섹션이 있어도 검증된 사실 목록에 넣지 않는다.
- 이미지·영상 관련 판단 (03-visual 담당)
- 검색을 무조건 수행하지 않는다 — 카드가 충분하면 생략한다.

## ④ 제약
- 카드만으로 특정 사실의 출처가 불충분하다고 판단되면 WebSearch/WebFetch로 추가로 확인할 수 있다. 카드가 충분하면 사용하지 않는다.
- 추가 검색 시 채택 가능한 출처는 **공공기관·공식 사이트·기사·논문·지도**뿐이다. **개인 블로그·유튜브는 출처로 사용 금지**.
- 추가 검색으로 얻은 사실은 반드시 출처(기관/URL 등)를 함께 저장하고, 카드 원본 출처와 구분해서 표시한다.
- 자료가 충돌하면(수치·날짜 등) 임의로 하나를 채택하지 말고 **"기록마다 다름"**으로 나란히 병기한다.
- **"정보가 없다/기록되지 않았다"는 서술 자체는 유효한 검증된 사실이다** — 빠진 정보로 착각해 `forbidden_topics`에 넣거나 누락시키지 않고, `verified_facts`에 그대로 남긴다.
- `⚠ 주의` 섹션에 "카드 밖의 다른 통설/이야기가 있지만 이 카드엔 없다"는 식의 예시가 있다면, 그 예시 내용 자체를 사실처럼 서술하지 않고 금지 목록 항목으로만 취급한다.
- "정확한 위치/수치/책임 소재를 하나로 단정할 수 없다"는 경고는 충돌(conflict)과 다른 성격이다 — 값 자체는 있지만 뭉뚱그리면 안 되는 경우이므로 `precision_guardrails`로 별도 분류한다.
- "출처 원문"/"안내판 원문" 섹션의 인용문은 **표현을 한 글자도 바꾸지 않고** 그대로 옮긴다.
- 카드의 지어내기 금지 항목은 **절대 확정 서술하지 않는다**.
- 카드 전체에 적용되는 공개 제한 플래그(예: "감수 전 외부 공개 금지")가 있으면 개별 사실이 아니라 **문서 전체의 메타데이터**로 취급하고 이후 모든 단계까지 그대로 전달되게 한다.

## ⑤ 출력 형식
이 호출에 함께 전달되는 JSON Schema(`Step01VerifyOutput`)를 정확히 따른다 — `location_id` / `verified_facts` / `sources` / `citation_guide` / `verbatim_quotes` / `forbidden_topics` / `conflicts` / `precision_guardrails` / `publication_flag`. `conflicts`(자료마다 값이 달라 병기해야 함)와 `precision_guardrails`(값은 하나지만 뭉뚱그리면 안 됨)는 서로 다른 필드이며 항상 둘 다 존재해야 한다(해당 없으면 빈 배열). 카드에 없는 섹션에 대응하는 필드는 빈 배열/값으로 두고 **내용을 지어내서 채우지 않는다**. `sources[]`의 `used_for_en`·`ref_en`(영문 번역)도 한국어와 동일한 방식으로 실제로 채운다 — 구조만 남기고 비워두지 않는다.

## ⑥ 성공 기준
- 카드의 모든 사실에 출처가 매칭돼 있다.
- 주의/금지 섹션이 요약·순화 없이 원문 그대로 반영됐다.
- "정보 없음"류 서술이 금지 목록에 잘못 들어가지 않았다.
- 인용문(`verbatim_quotes`)이 카드 원문과 한 글자도 다르지 않다.
- 카드에 없는 섹션은 억지로 채우지 않고 빈 값으로 처리됐다.
- `publication_flag`가 출력에 포함되어 있다.

## 공통 규칙 (모든 스킬 공통)
1. **출처 표기 필수** — 카드 밖 자료도 가능하나 출처 명시. 개인 블로그·유튜브 금지
2. **쉬운 언어** — 청소년·외국인이 배경지식 없이 읽을 수 있게
3. **사실 vs 연출 구분** — AI 생성 이미지·영상엔 `[연출]` 표시
4. **지어내기 금지** — 카드에 없는 내용은 채우지 않음
5. **충돌 시 병기** — 수치·날짜가 자료마다 다르면 '기록마다 다름'으로 나란히 표기
