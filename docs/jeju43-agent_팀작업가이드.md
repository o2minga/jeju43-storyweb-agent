# 제주 4·3 스토리웹 에이전트 — 팀 작업 가이드

**저장소**: `jeju43-storyweb-agent`
**팀**: 박이현(A) · 백민하(B)
**목표**: 유적지 카드(.md)를 넣으면 → 검증 → 이야기 → 비주얼·오디오 → 웹페이지 + 챗봇이 자동으로 나오는 **반복 가능한 에이전트**

## 3. ⚠ 가장 중요한 구조적 리스크와 대응

### 문제
기획문서의 개발 우선순위는 `① → ② → ⑤ → ⑧` (뼈대) 다음에 `③ ④ ⑥ ⑦` (살)입니다.
그런데 **뼈대 4개가 전부 박이현 담당**입니다. 순서대로만 가면:

- 박이현: 처음부터 끝까지 계속 바쁨 (크리티컬 패스)
- 백민하: 02가 나올 때까지 **할 일이 없음** → 2주 일정에서 치명적

### 대응 — `samples/` 를 계약서처럼 쓴다

**Day 1에 두 사람이 함께 `samples/` 안의 JSON 스키마를 먼저 확정합니다.**
그러면 백민하는 실제 02 결과물을 기다리지 않고, 가짜 샘플만 보고 03·04·07을 병렬로 개발할 수 있습니다.

```
[Day 1] 둘이 같이 samples/*.json 형식 확정 (실제 데이터 아니어도 됨)
   ↓
[Day 2~] 박이현: 01 → 02 → 05 → 08 (실제 구현)
         백민하: 03 → 04 → 07 → 06 (샘플 보고 병렬 구현)
   ↓
[중반] 박이현의 02 실제 출력 ↔ 백민하의 샘플 기반 결과물 연결 테스트
```

### samples/ 파일 목록 (Day 1에 함께 작성)

| 파일 | 만드는 사람 | 쓰는 사람 | 용도 |
|---|---|---|---|
| `01-verify-output-example.json` | 박이현 | 박이현(02) | 검증 정리본 4종 세트 |
| `02-story-output-example.json` | **박이현** | **백민하(03·04·07)** | **가장 중요** — 원고·프롬프트·타임라인·KB |
| `03-visual-output-example.json` | 백민하 | 박이현(05) | 이미지·영상 경로 + [연출] 표시 |
| `04-audio-output-example.json` | 백민하 | 박이현(05) | mp3 경로 + 싱크 타임라인 |
| `07-chatbot-output-example.json` | 백민하 | 박이현(05) | KB JSON + 가드레일 + 모달 스크립트 |

> **스키마를 바꾸면 반드시 상대방에게 즉시 알린다.** 이게 이 프로젝트에서 가장 자주 터질 사고입니다.

## 4. 모든 스킬이 지키는 공통 규칙 (감점 방지선)

**8개 SKILL.md 전부에 이 5줄이 들어가야 합니다.** 예쁜 것보다 규칙 준수가 우선이고, 위반이 더 큰 감점입니다.

1. **출처 표기 필수** — 카드 밖 자료도 가능하나 출처 명시. 개인 블로그·유튜브 금지
2. **쉬운 언어** — 청소년·외국인이 배경지식 없이 읽을 수 있게
3. **사실 vs 연출 구분** — AI 생성 이미지·영상엔 `[연출]` 표시
4. **지어내기 금지** — 카드에 없는 내용(아이의 생사, 발포 위치 등)은 채우지 않음
5. **충돌 시 병기** — 수치·날짜가 자료마다 다르면 '기록마다 다름'으로 나란히 표기

## 5. SKILL.md 공통 템플릿

모든 스킬은 **6개 원칙** 구조로 작성합니다. 8개 파일이 같은 뼈대여야 나중에 합쳤을 때 매뉴얼로 읽힙니다.

```markdown
---
name: 01-verify
description: (이 스킬을 언제 써야 하는지 — 트리거 조건까지 구체적으로)
---

# 스킬 이름 ‹별명›

## ① 목표
## ② 맥락
## ③ 범위 (포함 / 제외)
## ④ 제약
## ⑤ 출력 형식
## ⑥ 성공 기준

## 공통 규칙 (5줄 — 위 4장 그대로)
## 입력 예시 / 출력 예시 (samples/ 파일 참조)
```

## 01-verify (문지기)

**목표**: 카드를 검증해 '믿고 써도 되는 사실'만 남기고 라벨을 붙인다. 파이프라인 신뢰성의 뿌리.

### 할 일
- [ ] `test-card/관덕정_카드.md` 구조 파악 (항목별로 어떻게 생겼는지)
- [ ] 카드 파싱 규칙 정의 (항목별 추출)
- [ ] 출처 유무 확인 로직
- [ ] 자료 간 충돌 검사 → '기록마다 다름' 병기 처리
- [ ] 지어내기 금지 항목(⚠주의) 목록화
- [ ] 부족할 때만 추가 검색 (공공기관·공식사이트·기사·논문·지도만 / 카드가 충분하면 검색 생략)
- [ ] 출력 4종 세트 확정 → `samples/01-verify-output-example.json`

### 출력 4종 세트
① 검증된 사실 목록 ② 출처 목록(카드/검색 구분) ③ 지어내기 금지 목록 ④ 충돌 병기 목록

### 클로드 코드 프롬프트 예시
```
skills/01-verify/SKILL.md 를 만들어줘.
유적지 카드(.md)를 파싱해서 ①검증된 사실 목록 ②출처 목록(카드/검색 구분)
③지어내기 금지 목록 ④충돌 병기 목록, 이 4종 세트를 출력하는 스킬이야.
test-card/관덕정_카드.md 를 읽고 실제 카드 구조에 맞게 파싱 규칙을 써줘.
추가 검색은 카드가 부족할 때만 하고, 공공기관·공식사이트·기사·논문·지도만 채택,
개인 블로그·유튜브는 금지라고 제약에 명시해줘.
목표/맥락/범위/제약/출력형식/성공기준 6개 원칙 구조로 작성해줘.
```

### 성공 기준
카드의 모든 사실에 출처가 매칭됨 · 금지 항목 빠짐없이 목록화 · 충돌 지점 병기 처리 · 추가 검색분에 출처 전부 부착

## 02-story (번역가) — **최우선 착수**

**목표**: 배경지식 없는 사람도 '왜 이 장소가 중요한지' 이해하는 이야기로 옮긴다. 이 과제의 심장.

> ⚠ **이 스킬의 출력 샘플이 백민하의 03·04·07 개발을 막고 있습니다. 샘플 JSON을 최우선으로 확정해서 공유하세요.**

### 할 일
- [ ] **`samples/02-story-output-example.json` 먼저 작성 후 백민하에게 공유** ← 최우선
- [ ] 어려운 용어 풀이 규칙 (예: 안무사 → 조선시대 지방 관리)
- [ ] '왜?' 연결고리 만들기 — 사건 인과 잇기
- [ ] 고정 뼈대 구성: 장소 소개 → 무슨 일 → 왜 기억
- [ ] 대상 모드 3종(중·고생 / 일반 성인 / 외국인) 톤 조절 — **사실·출처·금지선은 3모드 동일, 톤만 변경**
- [ ] 타임라인 이벤트 데이터 추출
- [ ] 챗봇 KB 기초 데이터 생성 (07이 받아 씀)
- [ ] 언어 라벨 구조 (ko 채움 / en 자리만 비움)

### 출력 5종
① 스토리 원고(도입·전개·마무리) ② 문장별 출처 ③ 03단계용 이미지 프롬프트 초안 ④ 타임라인 이벤트 데이터 ⑤ 챗봇 Q&A/KB 데이터

### 클로드 코드 프롬프트 예시
```
먼저 samples/02-story-output-example.json 을 만들어줘.
①스토리 원고(도입·전개·마무리) ②문장별 출처 ③이미지 프롬프트 초안
④타임라인 이벤트 배열 ⑤챗봇 KB Q&A 배열이 들어가고,
각 텍스트 필드는 {"ko": "...", "en": ""} 형태의 언어 라벨 구조로 해줘.
관덕정 기준 그럴듯한 더미 데이터로 채워줘 — 팀원이 이걸 보고 병렬 작업할 거야.

그 다음 skills/02-story/SKILL.md 를 6개 원칙 구조로 작성해줘.
제약에 반드시 넣을 것: 1단계 금지 목록 준수, 빈칸은 상상으로 메우지 말고
'기록에 남아 있지 않다'로 정직하게 표현, 날짜·사망자 수 같은 사실 자체는 손대지 않음.
```

### 성공 기준
배경지식 없는 독자가 장소의 중요성을 이해함 · 어려운 용어 전부 풀림 · 금지선 한 번도 안 넘음 · 모드 변경 시 사실 그대로·톤만 변함 · 타임라인/KB 정상 추출

## 05-assemble (조립공)

**목표**: 02 원고 + 03 비주얼 + 04 오디오 + 07 챗봇을 받아 브라우저에서 열리는 `.html` 한 장으로 조립. **반복성을 담보하는 자리.**

- [ ] 세로 스크롤형 기본 템플릿 설계
- [ ] 블록 컴포넌트 정의: 글 · 타임라인 · 인용 · 이미지 · 영상 · 오디오 플레이어 · 출처
- [ ] **없는 요소의 블록은 자동 생략** (연표 없으면 타임라인 블록 제외)
- [ ] `design.md`(또는 design 파일)로 스타일 분리 → **파일 교체만으로 전체 톤 변경**
- [ ] 인터랙티브 타임라인 연동
- [ ] 챗봇 모달 스크립트 연동 (우측 하단 floating 버튼)
- [ ] 출처 하단 규칙대로 표기 / 이미지·영상 아래 `[연출]` 표시
- [ ] `output/관덕정.html` 출력

### 클로드 코드 프롬프트 예시
```
skills/05-assemble/SKILL.md 를 만들어줘.
samples/02-story-output-example.json, 03-visual, 04-audio, 07-chatbot 샘플을 입력으로 받아
세로 스크롤형 .html 한 장으로 조립하는 스킬이야.

블록(글/타임라인/인용/이미지/영상/오디오/출처)을 골라 쌓되,
해당 데이터가 없으면 그 블록은 자동 생략하도록 규칙을 명시해줘.
스타일은 design 파일로 분리해서 파일 교체만으로 톤이 바뀌는 구조로 설계해줘.
하단 출처 표기와 AI 생성물 [연출] 표시는 필수 규칙으로 넣어줘.
```

### 성공 기준
**카드만 바꿔 넣으면 다음 장소도 같은 품질의 페이지가 나옴(반복성)** · 출처 하단 표기 · AI 생성물에 [연출] · 오디오/챗봇 모달 정상 작동 · design 파일 교체로 톤 변경

**목표**: 사람 최종 확인 전 규칙 자동 점검 + 출처 대장 생성. 함께공이 별도 요청한 관리용 문서.

### 할 일

  - 용어 풀이 여부
  - 챗봇 KB 일치 여부
- [ ] 통과/보류 + 걸린 항목 표시 출력
- [ ] **출처 대장(.md)** 생성 — 내용 · 출처 · 어디에 쓰였나
- [ ] ⚠ **AI 생성 이미지·영상·오디오는 대장에서 제외** (웹 안에서 [연출]로만 관리)

### 클로드 코드 프롬프트 예시
```
skills/08-review/SKILL.md 를 만들어줘.
완성된 .html과 각 단계 산출물을 받아 6개 항목(출처 누락 / [연출] 표시 /
지어내기 / 사실 일치 / 용어 풀이 / 챗봇 KB 일치)을 자동 점검하고
통과·보류를 표시하는 스킬이야.

동시에 출처 대장(.md)을 생성하는데, 실제 출처가 있는 것만 포함해줘 —
카드에서 온 사실, 추가 검색 사실, 실제 문헌 이미지만.
AI 생성 이미지·영상·오디오는 대장에서 반드시 제외하도록 제약에 명시해줘.
```

### 성공 기준
규칙 위반이 사람 확인 전에 걸러짐 · 대장으로 모든 사실·실제 이미지의 근거 추적 가능 · 대장에 AI 생성물 안 섞임

## 03-visual (미술감독)

**목표**: 장면에 맞는 이미지·짧은 영상. 잔인·사실적 재현은 피하고, 문헌 이미지 우선, **톤 통일**.

> 이 작업의 가장 흔한 실패는 '결과물마다 스타일 제각각 → 몰입 붕괴'입니다. 톤 통일이 핵심 과제예요.

### 할 일
- [ ] **재현 금지 게이트** 설계 — 생성 전 반드시 통과
      (예: 총살 장면 → 텅 빈 광장 · 흩어진 신발 같은 상징으로 대체)
- [ ] 문헌 이미지 우선 검색 로직 (있으면 AI보다 우선)
- [ ] `art-style` 파일 작성 — 화풍 · 채도 · 색감 · 분위기
- [ ] 모든 AI 생성 시 art-style 자동 첨부 → 톤 유지
- [ ] Higgsfield MCP 연동해 이미지·숏폼 영상 생성
- [ ] 모든 AI 생성물에 `[연출]` / 'AI 생성' 표시
- [ ] `samples/03-visual-output-example.json` 작성 → 박이현에게 공유

### 절대 생성 금지
- 잔인한 피해 장면 직접 묘사
- 실존 인물(피해자·생존자·가해자) 얼굴 복제

### 클로드 코드 프롬프트 예시
```
skills/03-visual/SKILL.md 를 만들어줘.
samples/02-story-output-example.json 의 이미지 프롬프트 초안을 입력으로 받아
이미지·숏폼 영상을 생성하는 스킬이야.

제약에 반드시 넣을 것:
- 생성 전 '재현 금지 게이트' 통과 필수. 총살·학살 장면 요청이 오면
  텅 빈 광장, 흩어진 신발 같은 상징으로 우회 변환하는 규칙을 구체적으로 써줘.
- 잔인한 피해 장면 직접 묘사, 실존 인물 얼굴 복제는 어떤 경우에도 금지.
- 문헌 이미지가 있으면 AI 생성보다 우선.
- art-style 파일(화풍·채도·색감·분위기)이 모든 생성에 자동 첨부돼 톤 통일.
- 모든 AI 생성물에 [연출] 표시.

art-style 파일 초안도 4·3이라는 소재에 맞게 같이 만들어줘.
```

### 성공 기준
잔인·재현 이미지 0건 · 문헌 이미지 우선 사용됨 · 여러 산출물이 '같은 손이 만든 것'처럼 일관 · 전부 [연출] 표시

## 07-chatbot (안내원)

**목표**: 검증된 사실 안에서만 답하는 4·3 전용 AI 안내원.

> ⚠ **05 조립 전에 완료되어야 합니다.** 실행 순서상 05보다 앞이에요.

### 할 일
- [ ] 02의 KB 기초 데이터 → RAG 지식베이스(JSON) 구축
- [ ] 환각 방지 프롬프트 가드레일 설계
- [ ] **KB에 없는 질문 → '기록에 명시되지 않은 내용입니다'로 정직하게 답변**
- [ ] 01의 지어내기 금지 목록을 가드레일에 반영
- [ ] 정치적 편향·과장된 감정 이입 배제 규칙
- [ ] 우측 하단 floating 버튼 → 모달 UI JS 스크립트
- [ ] `samples/07-chatbot-output-example.json` 작성 → 박이현에게 공유

### 클로드 코드 프롬프트 예시
```
skills/07-chatbot/SKILL.md 를 만들어줘.
samples/02-story-output-example.json 의 KB 데이터를 입력으로 받아
①KB JSON ②프롬프트 가드레일 설정 파일 ③웹 연동용 JS 모달 스크립트를 출력하는 스킬이야.

제약에 반드시 넣을 것:
- 1단계 검증 사실과 지어내기 금지 목록 안에서만 답변
- KB에 없는 질문은 '기록에 명시되지 않은 내용입니다'로 정직하게 답변
- 정치적 편향성, 과장된 감정 이입, 주관적 판단 금지
- 우측 하단 floating 버튼으로 모달 구동

가드레일 시스템 프롬프트 초안도 같이 작성해줘.
```

### 성공 기준
검증 근거 내에서만 일관 답변 · 환각/오답 0건 · floating 버튼으로 챗봇 창 정상 구동

## 04-audio (음향감독)

**목표**: 원고 기반 TTS 오디오 가이드 + 장소성에 맞는 차분한 BGM.

### 할 일
- [ ] 02 원고 → 자연스러운 AI TTS 음성 추출 (한국어 ko)
- [ ] **고유명사·역사 용어 발음 사전** 적용 (관덕정, 4·3, 안무사 등)
- [ ] 4·3에 적합한 톤앤매너 BGM 매칭
- [ ] BGM ↔ 음성 음량 밸런싱
- [ ] 스크립트 싱크 타임라인 데이터 생성
- [ ] 웹 오디오 에셋 패키지 출력 (05 오디오 플레이어 블록에 즉시 연동)
- [ ] 영어(en)는 02 영어 대본 완성 후 대응 — **현재는 자리만**
- [ ] `samples/04-audio-output-example.json` 작성 → 박이현에게 공유

### 제약
- 자극적·과장되지 않은 차분하고 객관적인 톤
- AI 음성 생성 시 출처 표기 명시
- **무단 상업용 BGM 금지** — 로열티 프리 또는 자체 AI 음악 에셋만

### 클로드 코드 프롬프트 예시
```
skills/04-audio/SKILL.md 를 만들어줘.
02 스토리 원고를 받아 ①오디오 가이드 MP3(ko) ②스크립트 싱크 타임라인 데이터
③웹 오디오 에셋 패키지를 출력하는 스킬이야.

제약에 반드시 넣을 것:
- 차분하고 객관적인 톤 (자극적·과장 금지)
- 고유명사·역사 용어 발음 사전 적용
- 무단 상업용 BGM 금지, 로열티 프리 또는 자체 AI 음악만
- 영어는 2단계 영어 대본 완성 후 대응, 현재는 구조상 자리만

관덕정·4·3 관련 고유명사 발음 사전 초안도 같이 만들어줘.
```

### 성공 기준
원고가 왜곡 없이 정확한 발음으로 읽힘 · BGM/음성 밸런스 양호 · 05 오디오 플레이어에 즉시 연동

## 06-map (현관문)

**목표**: 여러 장소를 제주 지도로 묶는 첫 화면. **'확장되는 구조'를 보여주는 증거.**

> 함께공이 로드맵에서 **1단계·우선 과제**로 지정한 부분입니다. 장소가 하나여도 구조를 보여주는 게 목적이에요.

### 할 일
- [ ] 장소 좌표(위경도) 수집
- [ ] 제주 지도 이미지 준비 (외부 API 키 불필요 → 오프라인에서도 열림)
- [ ] **좌표 → 지도 이미지 픽셀 위치 변환 규칙**을 스킬 내부에 포함
- [ ] 점마다 미리보기 카드 (이름 · 한 줄 소개 · 대표 이미지)
- [ ] 05가 만든 스크롤 페이지로 링크 연결
- [ ] 확대 · 축소 · 이동(팬) 기능
- [ ] **지도를 조작해도 점은 제자리에 고정**
- [ ] 실제 지도 라이브러리(구글맵 등)는 범위 밖 — 자리만 남김

### 클로드 코드 프롬프트 예시
```
skills/06-map/SKILL.md 를 만들어줘.
장소 목록(이름·좌표·한 줄 소개·대표 이미지·링크)을 받아
제주 지도 이미지 위에 점을 찍은 인덱스 .html을 출력하는 스킬이야.

제약에 반드시 넣을 것:
- 간단 이미지 지도 방식 (외부 API 키 불필요, 오프라인에서도 열림)
- 확대·축소·이동해도 점이 지도상 정확한 위치에 고정
- 위경도를 지도 이미지 픽셀 좌표로 변환하는 규칙을 스킬 안에 포함
- 카드 추가만으로 장소가 늘어나는 구조

좌표 변환 로직도 실제 동작하게 구현해줘.
```

### 성공 기준
점 클릭 시 해당 장소 이야기로 이동 · 확대/축소/이동 작동 · 지도 조작과 무관하게 점 위치 고정 · **카드 추가만으로 장소 증가**

# 공동 작업 규칙

## 브랜치 전략

스킬마다 폴더가 분리돼 있어서 **스킬 단위로 브랜치를 파면 충돌이 거의 없습니다.**

```
main
 ├── feature/01-verify      (박이현)
 ├── feature/02-story       (박이현)
 ├── feature/03-visual      (백민하)
 ├── feature/04-audio       (백민하)
 ├── feature/05-assemble    (박이현)
 ├── feature/06-map         (백민하)
 ├── feature/07-chatbot     (백민하)
 └── feature/08-review      (박이현)
```

**한 스킬 끝나면 바로 PR → merge → 다음 브랜치.** 브랜치를 오래 들고 있으면 나중에 충돌이 커집니다.

## 반복 사이클

1. **작업** — 자기 브랜치에서 클로드 코드로 개발
2. **커밋** — `지금까지 작업한 내용 커밋해줘. 메시지는 "01-verify 스킬 초안"으로.`
3. **Push** — `지금 브랜치 push 해줘.`
4. **PR** — GitHub → "Compare & pull request" → 제목/설명 → Create
5. **리뷰 & Merge** — 상대방이 Files changed 확인 후 Merge
6. **최신화** — 둘 다 `main으로 이동해 pull 받고, 내 브랜치에 main을 merge해줘.`

## 충돌 주의 파일

아래 파일은 **수정 전에 상대방에게 알리세요.**

- `samples/` 안의 모든 JSON (인터페이스 계약)
- `test-card/관덕정_카드.md` (공용 테스트 재료)
- `CLAUDE.md` (프로젝트 맥락)
- `README.md`

## 스킬 완성 직후 필수 절차

각 스킬을 만든 직후, **관덕정 카드로 실제 한 바퀴 돌려 작동하는지 팀이 함께 테스트**합니다 (기획문서의 '스킬 자체 검수 B'). 별도 문서를 만드는 게 아니라 제작 직후 바로 돌려보는 절차예요.

## CLAUDE.md 유지

merge 될 때마다:
```
방금 merge된 내용을 CLAUDE.md에 반영해줘.
```
