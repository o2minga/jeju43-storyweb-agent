# skills/02-story/spec.md — 02-story 스킬 상세 스펙 ‹번역가›

> 이 문서는 `AGENT-SPEC.md`의 일반 원칙 위에서 02-story만의 세부 규칙을 정의한다.
> **특정 유적지의 실제 역사적 사실이나 문장은 예시로도 포함하지 않는다.** 아래 예시는 전부 플레이스홀더다 — 어떤 카드가 들어와도 이 문서 내용은 그대로 유지되어야 한다.

---

## 1. 목표

01-verify가 넘긴 "믿을 수 있는 사실"을, 배경지식이 전혀 없는 사람(청소년·외국인)도 "왜 이 장소가 중요한지" 이해할 수 있는 이야기로 옮긴다. 이 스킬이 이 과제 전체의 심장이다.

**스토리텔링의 정의**: 드라마 각색이 아니라 "맥락화"다. 위키식 건조한 요약도 아니고, 과장된 극적 서술도 아니다. 사실을 이해하게 만드는 배경 설명을 채우는 것이 목적이다.

---

## 2. 입력

01-verify의 출력(`01-verify.json`)을 그대로 받는다. 특히 아래 필드를 반드시 참고해야 한다:

| 01의 필드 | 02에서 쓰는 방식 |
|---|---|
| `verified_facts` | 이야기의 사실적 근거 — 이 안의 내용만 쓸 수 있음 |
| `forbidden_topics` | 절대 채워 넣거나 언급하지 않을 항목 |
| `conflicts` | 자료마다 값이 달라 병기해야 하는 항목 — 본문에도 "기록마다 다름" 형태로 반영 |
| `precision_guardrails` | 뭉뚱그려 서술하면 안 되는 표현 규칙 |
| `verbatim_quotes` | 필요시 인용은 가능하나, 문장 자체는 수정 불가 |
| `publication_flag` | 그대로 02 출력에도 포함시켜 이후 단계(05)까지 전달 |

카드 원문 자체도 함께 입력으로 받아, 01이 놓쳤을 수 있는 맥락(장소의 분위기, 지리적 관계 등 사실 판단이 아닌 서술적 요소)을 참고할 수 있다.

---

## 3. 범위 (포함 / 제외)

**포함**
- 어려운 용어 풀이 (전문 용어·옛 직책명·역사 용어 등을 이해하기 쉬운 말로 설명)
- "왜?"의 연결고리 만들기 (사건의 인과관계를 잇기)
- 정해진 뼈대로 구성: **장소 소개 → 무슨 일이 있었나 → 왜 지금까지 기억되는가**
- 대상 모드별 톤 조절 (중·고생 / 일반 성인 / 외국인)
- 인터랙티브 타임라인 데이터 추출
- AI 챗봇 지식베이스(KB) 기초 데이터 생성 (질문-답변 쌍)
- 03단계(비주얼)가 바로 쓸 수 있는 이미지 프롬프트 초안 작성
- 이야기 확인 퀴즈 문항 생성 (3~5개, 객관식) — story에 이미 쓴 사실을 재확인하는 용도로만 사용

**제외**
- 사건의 사실 자체(날짜·수치 등)를 새로 판단하거나 수정하는 것 — 이건 01의 영역이며, 02는 01이 검증한 사실만 그대로 사용한다
- 검증(01), 이미지 생성(03), 웹페이지 조립(05)은 각자의 스킬이 담당

---

## 4. 일반 처리 원칙 (카드 내용과 무관하게 항상 적용)

1. **01의 `forbidden_topics`를 글 쓰는 내내 절대 넘지 않는다.** 빈칸이 있다고 상상으로 메우지 않고, "이 부분은 기록에 남아 있지 않다"처럼 정직하게 표현한다.

2. **대상 모드(중·고생 / 일반 성인 / 외국인)를 바꿔도 사실·출처·금지선은 완전히 동일해야 한다.** 바뀌는 건 오직 **문장의 톤과 설명의 깊이**뿐이다. (예: 같은 사실이어도 중·고생 모드는 배경 설명을 더 자세히, 외국인 모드는 문화적 전제를 더 풀어서 설명하는 식 — 사실 관계 자체는 손대지 않음)

3. **언어 라벨 구조를 지킨다.** 한국어(`ko`)와 영어(`en`) 모두 이 단계에서 실제로 채운다 — `en`을 구조만 남기고 비워두지 않는다. 사실 자체(수치·날짜·인과관계)는 `ko`와 완전히 같은 내용을 영어로 옮긴 것이어야 하며, 번역 과정에서 새 정보를 더하거나 빼지 않는다.

4. **01의 `precision_guardrails`에 명시된 표현 규칙을 문장 작성 시 그대로 반영한다.** (예: 특정 항목을 하나로 뭉뚱그려 서술하지 말라는 규칙이 있으면, 이야기 문장에서도 그 구분을 유지)

4-1. **01의 `conflicts`(자료마다 값이 다른 항목)는 하나를 임의로 고르지 않고, 본문에서도 "기록마다 다름" 형태로 병기한다.** `conflicts`와 `precision_guardrails`는 서로 다른 문제이므로 혼동하지 않는다 — conflicts는 "여러 값 중 뭘 골라야 할지 모름", precision_guardrails는 "값은 하나인데 뭉뚱그리면 안 됨".

5. **01의 `publication_flag`를 02의 출력에도 그대로 포함시킨다.** 이 플래그는 개별 스킬이 판단하는 게 아니라 카드 전체에 적용되는 값이므로, 02가 임의로 바꾸지 않고 그대로 전달만 한다.

---

## 5. 제약

- 사건의 사실 자체(날짜·수치·인과관계의 구체적 내용)는 01이 검증한 범위를 벗어나 새로 서술하지 않는다
- 어려운 용어는 반드시 풀어서 설명하되, 원래 용어 자체를 삭제하지 않고 "용어 (쉬운 설명)"처럼 병기하는 것을 권장
- 타임라인 이벤트는 01의 `verified_facts`에서 날짜가 확인되는 사실만 추출한다 (날짜가 불명확한 사실은 타임라인에서 제외하거나 "시기 불명"으로 표기)
- 챗봇 KB의 질문-답변은 01의 `forbidden_topics`에 해당하는 질문이 들어올 경우를 대비해, "기록에 명시되지 않은 내용입니다" 같은 답변 예시도 최소 1개 포함한다 (07단계 가드레일 테스트용)
- 퀴즈 문항은 `story`·`timeline_events`에 이미 쓴 사실만 재확인한다 — 카드나 01에 없는 새 주장을 퀴즈 보기·해설에 만들어 넣지 않는다(지어내기 금지 원칙과 동일하게 적용)

>

## 7. 성공 기준

- [ ] 배경지식 없는 독자가 읽고 이 장소의 중요성을 이해할 수 있다
- [ ] 어려운 용어가 모두 풀어서 설명됐다
- [ ] 01의 `forbidden_topics`를 한 번도 넘지 않았다
- [ ] 01의 `conflicts`가 있다면 본문에서도 "기록마다 다름"으로 병기됐다 (하나로 임의 선택하지 않음)
- [ ] 대상 모드를 바꿔도 사실·출처·금지선은 동일하고 톤만 달라진다
- [ ] 타임라인 이벤트가 정상 추출되었고, 날짜 불명확한 사실은 적절히 처리됐다
- [ ] 챗봇 KB에 가드레일 테스트용 질문(금지 항목 관련)이 최소 1개 포함되어 있다
- [ ] 01의 `publication_flag`가 그대로 전달됐다
- [ ] 언어 라벨 구조(`ko`·`en` 모두 채움)가 모든 텍스트 필드에 일관되게 적용됐고, `en`이 빈 문자열로 남은 곳이 없다
- [ ] 퀴즈 문항 3~5개가 있고, 전부 `story`에 이미 쓴 사실만 재확인하며 정답 하나가 명확히 표시되어 있다
- [ ] `sources_by_sentence[].text_snippet.ko`가 전부 해당 문단(`story.intro`/`development`/`closing`) 텍스트의 정확한 부분 문자열이다(05 조립이 실패하지 않는 최소 조건)
- [ ] `sources_by_sentence[].source`가 전부 01의 `verified_facts[].source.ref`와 일치(또는 포함 관계)한다 — `sources[]`/`citation_guide[]`의 서지 정보를 옮겨 쓰지 않았다
- [ ] **(중요) 이 스킬을 다른 유적지의 01 출력으로 실행해도 위 기준을 동일하게 만족한다** — 특정 카드에서만 통하는 규칙이 섞여 있지 않은지 최종 점검
