# skills/03-visual/spec.md — 03-visual 스킬 상세 스펙 ‹미술감독›

> 이 문서는 `AGENT-SPEC.md`의 일반 원칙 위에서 03-visual만의 세부 규칙을 정의한다.
> **특정 유적지의 실제 역사적 사실이나 장면은 예시로도 포함하지 않는다.** 아래 예시는 전부 플레이스홀더다 — 어떤 카드가 들어와도 이 문서 내용은 그대로 유지되어야 한다.
> 실행용 요약 지시문은 `SKILL.md`, 톤 통일 근거는 `art-style.md`에 있다. 이 문서는 판정·변환·출력 스키마의 상세를 담는다.

---

## 0. 아키텍처 위치 (지금 단계)

`AGENT-SPEC.md` 5장 기준 **03-visual은 B그룹(미디어 생성형)** 이다.

- Higgsfield 등 자동 이미지 생성 API를 아직 못 쓴다. 대신 **반자동(사람 개입) 워크플로우**로
  동작한다: 03은 재현 금지 게이트(safety_gate)를 통과·변환시킨 최종 프롬프트까지만 만들고,
  실제 이미지·영상 파일은 관리자가 그 프롬프트를 외부 AI 도구에 직접 넣어 만든 뒤 정해진
  경로(`assets/{location_id}/{prompt_id}.png`, 영상이면 `.mp4`)에 넣는다.
- 03은 실행할 때마다 그 경로에 파일이 이미 있는지 확인해서 자산마다 `status`를
  `"ready"`(있음) 또는 `"awaiting_manual_generation"`(아직 없음)으로 채운다 — 관리자가
  파일을 넣고 나면 별도 승인 절차 없이 다음 실행에서 자동으로 `"ready"`로 바뀐다.
  아직 안 만들어진 이미지는 관리자가 보기 좋게 `output/{location_id}/03-image-prompts-for-admin.md`에
  따로 정리한다(⑦ 참고).
- 나중에 실제 이미지 생성 API 키가 생기면, 이 반자동 대기(`awaiting_manual_generation`) 자리에
  자동 생성 호출을 끼워 넣으면 된다 — 입출력 형태(스키마)는 지금 확정해 둔다.
- 따라서 이 spec의 핵심은 "무엇을 어떤 모양으로 내보내는가"와 "생성 전 어떤 게이트를 통과시키는가"이다. 실제 렌더링 화질·모델 파라미터는 범위 밖.

## 1. 목표

02-story가 넘겨준 이미지 프롬프트 초안을, **잔인·사실적 재현을 피하고 문헌 이미지를 우선**하며 **톤을 하나로 통일**한 비주얼 자산 메타데이터로 변환한다. 카드가 어떤 유적지이든, 폭력·피해·특정 인물을 직접 재현하지 않고 상징으로 우회하는 규칙은 동일하게 적용된다.

## 2. 입력 — 02-story 출력의 일부

`samples/02-story-output-example.json`의 아래 부분만 사용한다(나머지 필드는 03이 건드리지 않는다).

- `location_id` — 자산 경로·묶음 식별자
- `image_prompts_draft[]` — 각 항목:
  - `prompt_id` — 초안 식별자
  - `scene.{ko,en}` — 장면 묘사 (ko 채움, en 자리)
  - `mood` — 분위기 힌트
  - `note_for_03` — **03에게 주는 지시.** "재현 금지 게이트 적용 대상" 등 지시가 있으면 최우선 적용

> `image_prompts_draft`가 비어 있거나 없으면 자산 없이 빈 결과(`assets: []`)를 리턴한다 — 억지로 만들지 않는다(방어적 처리).

## 3. 범위 (포함 / 제외)

**포함**
- 각 프롬프트 초안을 재현 금지 게이트에 통과·변환시켜 최종 생성 프롬프트로 만듦
- 문헌 이미지(공공기관·기록물) 우선 탐색 → 있으면 AI 생성보다 우선 채택
- art-style.md 톤을 자동 첨부한 AI 이미지/숏폼 영상 (지금은 placeholder)
- 각 자산에 `[연출]` 여부·게이트 결과·출처 메타데이터 부착
- 05-assemble이 바로 읽는 출력 JSON 산출
- 아직 안 만들어진(=`awaiting_manual_generation`) 이미지만 골라 관리자용 프롬프트 문서(`03-image-prompts-for-admin.md`) 산출

**제외**
- 스토리 텍스트·타임라인·챗봇 KB 판단 (02·07)
- 웹페이지 조립 (05) / 오디오 (04) / 지도 좌표 (06)
- 실제 생성 모델의 화질·해상도·프레임 튜닝 (placeholder 단계 범위 밖)

## 4. 게이트 처리 로직 (카드 내용과 무관하게 항상 적용)

특정 카드에서 발견된 규칙이 아니라, **어떤 장면 프롬프트든 발생할 수 있는 패턴**이므로 매 자산마다 순서대로 적용한다.

### 4-1. 판정 (Detect)
프롬프트(초안 `scene` + `note_for_03`)에 아래 금지 요소가 있는지 검사한다.
- (a) 폭력 행위 장면 — 총살·처형·학살·구타·연행 등
- (b) 피해 신체의 직접 묘사 — 시신·부상·피 등
- (c) 특정 실존 인물(피해자·생존자·가해자)의 식별 가능한 얼굴
- `note_for_03`에 "재현 금지 게이트 적용 대상"이 명시돼 있으면 (a)~(c) 감지 여부와 무관하게 변환 대상으로 본다.

### 4-2. 분기 (Branch)
- **통과(passed)**: (a)(b)(c) 어디에도 해당 없음 → art-style 첨부 후 그대로 생성.
- **변환(converted)**: 하나라도 해당 → 직접 묘사를 폐기하고 아래 대응표로 **상징 우회 변환**한 장면만 생성.
- **포기(skipped)**: 상징으로도 안전하게 대체할 수 없으면 생성 자체를 포기 → 문헌 이미지 또는 다른 상징 자산으로 대체하고 사유를 남긴다.

### 4-3. 우회 변환 대응표 (장소 무관 · 항상 동일)

| 요청된(금지) 장면 | → 상징으로 우회 변환 |
|---|---|
| 총살·처형 장면 | 텅 빈 광장, 아무도 없는 마당, 바닥에 흩어진 신발, 빈 의자 하나 |
| 시신·피해자 | 흰 천이 덮인 형체(신체 노출 없음), 놓인 꽃 한 송이, 빈 자리 위의 빛 |
| 폭력·구타·연행 | 부서진 문, 길게 늘어진 그림자, 열린 채 비어 있는 방 |
| 불타는 마을·방화 | 다 타고 굴뚝만 남은 터, 식은 재, 무너진 돌담 |
| 총소리·발포 순간 | 인물 없는 공간에 흐린 공기, 흩어지는 새 |
| 특정 인물의 얼굴 | 원경·뒷모습·실루엣, 얼굴은 비특정(식별 불가) |

### 4-4. 문헌 이미지 우선 (Detect보다 앞서 시도 가능)
- AI 생성 전에 공공기관·공식 사이트·기록물의 문헌 이미지가 있는지 먼저 확인한다.
- 있으면 AI 생성보다 우선 채택하되, 폭력·피해 신체가 노출된 기록 사진은 채택하지 않는다.
- 문헌 이미지는 실제 기록이므로 `[연출]`을 붙이지 않고, 출처를 반드시 표기한다(개인 블로그·유튜브 금지).

## 5. 제약

- 잔인한 피해 장면 직접 묘사, 실존 인물 얼굴 복제는 **어떤 경우에도 생성 금지**(우회로도 안 되면 포기).
- art-style.md는 **모든 AI 생성 프롬프트에 자동 첨부**한다. 스타일을 프롬프트에 하드코딩하지 않는다(파일 교체만으로 전체 톤 변경).
- 모든 AI 생성물에 `[연출]` 표시(`is_ai_generated:true`, `label:"[연출]"`).
- 기록마다 다른 사실은 이미지로 하나를 확정 짓지 않는다 → 상징·분위기로 처리(충돌 시 병기 원칙의 비주얼 버전).
- 카드에 없는 장면을 이미지로 만들어내지 않는다(지어내기 금지).

## 6. 출력 형식 (JSON 스키마)

아래 값은 전부 예시(플레이스홀더)다. 실제 실행 시 카드·프롬프트 내용에 맞게 채워진다.

```json
{
  "location_id": "{장소_식별자}",
  "art_style_ref": "skills/03-visual/art-style.md",
  "assets": [
    {
      "asset_id": "vis-01",
      "source_prompt_id": "{02의 prompt_id}",
      "type": "{image | video | archival}",
      "path": "assets/{location_id}/{prompt_id}.{png|mp4}",
      "duration_sec": "{video일 때만}",
      "is_ai_generated": true,
      "label": "[연출]",
      "gate": "{passed | converted | skipped}",
      "gate_reason": "{변환/포기 사유 — passed면 통과 근거}",
      "final_prompt": "{art-style 첨부된 최종 생성 프롬프트, archival/skipped면 null}",
      "source": "{AI 생성(관리자가 외부 도구로 직접 생성) | AI 생성(관리자 생성 대기 중) | 문헌 이미지의 실제 출처}",
      "caption": {"ko": "{장면 캡션}[연출]", "en": ""},
      "status": "{awaiting_manual_generation | ready — archival/skipped면 생략 가능}"
    }
  ],
  "gate_summary": {
    "total": 0, "passed": 0, "converted": 0, "skipped": 0,
    "note": "{게이트 통계 요약}"
  }
}
```

- `path`는 프로젝트 루트 기준 `assets/{location_id}/{prompt_id}.{ext}` — 관리자가 실제 결과 파일을 놓는 자리와 정확히 같다. 03은 이 경로에 파일이 이미 있는지 확인해서 있으면 `status:"ready"`, 없으면 `status:"awaiting_manual_generation"`으로 채운다.
- 문헌 이미지: `type:"archival"`, `is_ai_generated:false`, `label` 없음/빈값, `final_prompt:null`, `source`에 실제 출처.
- 생성 포기 자산: `gate:"skipped"`로 남기고 대체 자산을 함께 표기.
- `image_prompts_draft`가 비면 `assets: []`, `gate_summary.total: 0`으로 두고 지어내지 않는다.

## 7. 성공 기준

- [ ] 게이트를 우회하지 않은 폭력·피해 직접 묘사가 **0건**이다
- [ ] 실존 인물 얼굴 복제가 **0건**이다
- [ ] `note_for_03`에 게이트 지시가 있는 프롬프트는 전부 `converted` 또는 `skipped`로 처리됐다
- [ ] 문헌 이미지가 있으면 AI 생성보다 우선 채택됐고 출처가 붙어 있다
- [ ] 모든 AI 생성물에 `is_ai_generated:true`와 `[연출]` 라벨이 있다
- [ ] 문헌 이미지에는 `[연출]`이 붙지 않았다(사실 자료와 혼동 없음)
- [ ] `status`가 `assets/{location_id}/{prompt_id}.{ext}`의 실제 파일 존재 여부와 항상 일치한다(관리자가 파일을 넣으면 다음 실행에서 자동으로 `ready`로 바뀐다)
- [ ] 아직 `ready`가 아닌 이미지는 전부 `output/{location_id}/03-image-prompts-for-admin.md`에 목록화됐다(누락 없음)
- [ ] art-style이 모든 AI 생성 프롬프트에 첨부돼 톤이 일관된다
- [ ] 출력 JSON이 05-assemble이 바로 읽는 스키마를 만족한다
- [ ] `image_prompts_draft`가 비었을 때 억지로 자산을 만들지 않았다(방어적 처리)
- [ ] **(중요) 다른 유적지 카드로 실행해도 위 기준을 동일하게 만족한다** — 특정 장소에서만 통하는 규칙이 섞이지 않았는지 최종 점검
