# skills/08-review/spec.md — 08-review 스킬 상세 스펙 ‹감수관›

> 이 문서는 `AGENT-SPEC.md`의 일반 원칙 위에서 08-review만의 세부 규칙을 정의한다.
> **특정 유적지의 실제 내용은 예시로도 포함하지 않는다.** 아래 예시는 전부 플레이스홀더다.
>
> ⚠ **이 스킬은 파이프라인의 마지막 안전장치다.** 여기서 애매하게 넘어가면 잘못된 결과물이 그대로 함께공에게 전달될 수 있다. 그래서 이 문서는 다른 스펙보다 더 엄격하게, "무엇을 pass/fail로 판단하는지"와 "판단할 수 없을 땐 어떻게 하는지"를 명시적으로 정의한다.

---

## 0. 아키텍처 위치 (지금 단계)

`AGENT-SPEC.md` 5장 기준 **08-review는 A그룹(추론형)** 이지만, 6개 점검 중 4개(①②④⑥)는 Claude를 호출하지 않는다.

- ①②④⑥은 `05-assemble.html`의 `data-source`/`data-fact-id`, `class="ai-generated"` 캡션, 01·02·07의 JSON을 코드로 직접 파싱·대조하면 판정이 끝나는 항목이라, **재현성**(5장의 "같은 입력이면 항상 같은 결과") 확보를 위해 코드로 처리한다.
- ⑤(용어 풀이)는 4장이 이미 "원칙적으로 항상 `needs_human`으로 분류한다"고 못 박아 둔 고정값이라 이 역시 Claude를 부를 필요가 없다.
- ③(지어내기 여부)만 의역·우회 서술 판단이 필요해 실제로 Claude를 호출한다 — 6개 중 Claude가 관여하는 유일한 항목.
- `overall_status`도 Claude가 정하지 않는다 — 6개 check의 status를 코드가 집계해서 결정한다.

## 1. 목표

완성된 결과물을 사람이 최종 확인하기 전에 **규칙 준수를 자동으로 점검**하고, 근거 추적이 가능한 **출처 대장**을 만든다.

**이 스킬이 반드시 지켜야 할 대원칙**: 08은 절대 "애매한 상태"로 끝나지 않는다. 모든 점검 항목은 아래 4가지 상태 중 하나로 명확히 귀결되어야 한다.

| 상태 | 의미 |
|---|---|
| `pass` | 기계적으로 확인했고 규칙을 지켰음 |
| `fail` | 기계적으로 확인했고 규칙 위반이 발견됨 — 어디서 뭐가 문제인지 구체적으로 기록 |
| `needs_human` | 기계적으로 100% 판단할 수 없어 사람 확인이 필요함 (실패로 간주하지 않되, 반드시 사람 확인 목록에 남김) |
| `blocked` | 이 항목을 점검하는 데 필요한 이전 단계 결과물 자체가 없어서 점검을 시작할 수 없음 |

> `pass`도 `fail`도 아닌 상태를 그냥 넘기거나 조용히 생략하는 것은 금지한다. 반드시 위 4가지 중 하나로 기록한다.

## 2. 입력 — 필요한 이전 단계 파일 전부

08은 시작하자마자 **아래 파일들의 존재 여부부터 확인**한다.

| 파일 | 필수 여부 | 없을 때 |
|---|---|---|
| `01-verify.json` | 필수 | 전체 검수를 `blocked`로 즉시 종료, 사유를 명확히 기록 |
| `02-story.json` | 필수 | 동일 |
| `07-chatbot.json` | 필수 | 동일 |
| `05-assemble.html` | 필수 | 동일 (검수 대상 자체가 없으므로) |
| `03-visual.json` | 있으면 확인, 자산 중 `status`가 `ready`가 아닌 게 하나라도 있으면 해당 체크만 `needs_human`으로 표시 | 파이프라인을 막지 않음 |
| `04-audio.json` | 위와 동일 | 파이프라인을 막지 않음 |
| `06-map.html` | 선택 — 있으면 함께 점검, 없으면 해당 항목만 생략 | 파이프라인을 막지 않음 |

**필수 파일이 하나라도 없으면, 나머지 점검을 절대 진행하지 않는다.** 부분적으로 점검하고 "일단 통과"처럼 보이는 결과를 내는 것이 가장 위험한 실패 모드이기 때문이다.

## 4. 자동 점검 6개 항목 — 각각 정확히 어떻게 판단하는지

### ① 출처 누락 여부

**방법**: `05-assemble.html`에서 `class="fact"`를 가진 모든 요소를 찾아, 각각이 `data-source` 속성을 가지고 있는지 확인. 하나라도 없으면 `fail`, 어떤 문장인지(`data-fact-id`) 구체적으로 기록.

**추가 확인**: `data-fact-id`가 `01-verify.json`의 `verified_facts` 또는 `02-story.json`의 사실 목록에 실제로 존재하는 id인지도 확인 (존재하지 않는 id를 참조하면 `fail`).

### ② `[연출]` 표시 여부

**방법**: `class="ai-generated"`를 가진 모든 요소에 `<figcaption>` 텍스트가 `[연출]`을 포함하는지 확인. 하나라도 없으면 `fail`.

**주의**: 03이 반자동 워크플로우(관리자가 외부 도구로 이미지를 직접 만드는 방식)라, `03-visual.json`의 AI 생성 자산 중 `status`가 `"ready"`가 아닌 것(`"awaiting_manual_generation"` 등, 아직 관리자가 실제 파일을 넣지 않은 것)이 하나라도 있거나 04가 여전히 placeholder면, 이 항목은 `needs_human`으로 표시하고 사유를 "관리자가 아직 만들지 않은 이미지가 있음(03-image-prompts-for-admin.md 참고) — 실제 자산 생성 후 재검수 필요"로 남긴다. `pass`로 잘못 표시하지 않는다 (아직 검증할 대상 자체가 없기 때문).

### ③ 지어내기 여부

**방법**: `02-story.json`의 `forbidden_topics` 목록에 있는 핵심 문구가 `05-assemble.html`의 본문 텍스트에 등장하는지 키워드 대조로 1차 스크리닝한다.

**한계 인정**: 이 항목은 완전히 기계적으로 판단하기 어렵다 (의역·우회 서술은 키워드 대조로 못 잡음). 그래서:
- 키워드가 그대로 발견되면 → `fail`
- 키워드는 안 보이지만 문장 수가 많거나 서술이 구체적인 구간이 있다면 → `needs_human` (해당 구간을 표시해서 사람이 다시 읽도록)
- 이 항목은 **절대 `pass`만으로 끝내지 않는다** — 항상 "사람이 한 번 더 읽어야 할 구간" 목록을 같이 낸다.

### ④ 사실 일치 여부

**방법**: `05-assemble.html`에 등장하는 모든 `data-fact-id`가 `01-verify.json`의 `verified_facts`에 실제로 존재하는지 대조. 없는 id 참조 → `fail`. 또한 `01`의 `conflicts`가 `02`에서 병기 처리(`conflicts_carried_forward`)됐는지, `precision_guardrails`가 `02`의 `precision_guardrails_applied`에 반영됐는지도 함께 확인한다. 반영 안 된 항목이 있으면 `fail`.

### ⑤ 용어 풀이 여부

**한계 인정**: "어려운 용어가 다 풀렸는지"는 기계적으로 판단하기 매우 어렵다. 이 항목은 **원칙적으로 `needs_human`으로 분류**한다. 다만 최소한의 자동 보조로, 02 원고에서 괄호 설명 없이 등장하는 한자어·전문용어 후보를 간단히 추출해 "확인이 필요할 수 있는 용어 목록"을 함께 제공한다 (참고용이지 판정 근거 아님).

### ⑥ AI 챗봇 지식베이스 일치 여부

**방법**: `07-chatbot.json`의 KB 항목 전체가 `02-story.json`의 `chatbot_kb`에 있던 항목과 사실적으로 어긋나지 않는지 대조 (질문 집합이 임의로 늘거나 줄지 않았는지, 답변이 02의 사실 범위를 벗어나지 않는지). 또한 02에서 넣어둔 "가드레일 테스트용 질문"이 07에서 실제로 정직하게 처리("기록에 명시되지 않은 내용입니다" 류)되고 있는지 확인. 처리 안 되어 있으면 `fail`.

## 5. 제약

- 위 4가지 상태(pass/fail/needs_human/blocked) 외의 값은 사용하지 않는다
- `needs_human`이 하나라도 있으면, 전체 결과의 최종 상태는 자동으로 **`보류(HOLD)`**다 — `needs_human`이 있는데 전체를 `통과(PASS)`로 표시하지 않는다
- 필수 파일 누락(`blocked`)이 하나라도 있으면, 나머지 항목은 아예 실행하지 않고 결과를 `실행 불가`로 명확히 표시한다
- 같은 입력으로 다시 실행하면 항상 같은 결과가 나와야 한다 (실행할 때마다 판단이 달라지면 안 됨 — 재현 가능성)

---

## 6. 출처 대장 — 별도 규칙

- 포함: 카드에서 온 사실(`verified_facts` 중 `source.type == "card"`), 추가 검색으로 얻은 사실(`source.type == "search"`), 실제 문헌 이미지(`data-origin="archive"`)
- **제외**: AI 생성 이미지·영상·오디오는 대장에 넣지 않는다 (`data-origin="ai"` 또는 `class="ai-generated"`인 것은 전부 제외 — 이건 웹 안에서 `[연출]`로만 관리)
- 각 항목은 반드시 "내용 / 출처 / 어디에 쓰였는가(어느 블록·어느 문장)"를 갖춰야 한다. 셋 중 하나라도 비어 있으면 대장에서 제외하고, 별도로 "출처 정보 불완전 항목" 목록에 남긴다 (조용히 누락시키지 않는다).

## 7. 출력 형식

### ① `review_result.json` (기계가 읽는 결과 — 다음 실행·자동화에 사용)

```json
{
  "location_id": "{장소_식별자}",
  "overall_status": "PASS | HOLD | 실행불가",
  "checks": [
    {
      "check_id": "01-source-missing",
      "name": "출처 누락 여부",
      "status": "pass|fail|needs_human|blocked",
      "issues": [
        {"location": "{data-fact-id 또는 html 위치}", "detail": "{구체적으로 무엇이 문제인지}"}
      ]
    },
    {
      "check_id": "02-ai-generated-label",
      "name": "[연출] 표시 여부",
      "status": "needs_human",
      "issues": [],
      "reason": "미디어 생성 자리표시자 단계 — 실제 자산 생성 후 재검수 필요"
    }
  ],
  "missing_required_files": [],
  "generated_at": "{ISO 타임스탬프}"
}
```

### ② `source-ledger.md` (사람이 읽는 출처 대장 — 함께공 감수·관리용)

```markdown
# 출처 대장 — {장소명}

| 내용 | 출처 | 사용 위치 |
|---|---|---|
| {검증된 사실 문장} | {출처명} | {웹페이지 내 블록/섹션} |

## 출처 정보 불완전 항목 (확인 필요)
- {내용/출처/사용위치 중 일부가 비어 있는 항목}
```

### ③ `review-summary.md` (사람 최종 확인용 요약)

```markdown
# 검수 요약 — {장소명}

**전체 상태**: {PASS | HOLD | 실행불가}

## 자동 통과 항목
- {check name}: pass

## 사람 확인이 필요한 항목
- {check name}: {사유 및 확인해야 할 위치}

## 규칙 위반 발견 항목
- {check name}: {구체적 위치와 내용}

## 다음 단계
{overall_status가 HOLD/실행불가일 때 무엇을 먼저 고쳐야 하는지 우선순위}
```

## 8. 성공 기준

- [ ] 필수 이전 단계 파일이 하나라도 없으면 즉시 `실행불가`로 명확히 표시되고, 부분 점검 결과가 나오지 않는다
- [ ] 6개 점검 항목 모두 pass/fail/needs_human/blocked 중 하나로 명시적으로 귀결된다 (애매하게 생략된 항목이 없다)
- [ ] `needs_human` 항목이 하나라도 있으면 `overall_status`가 절대 `PASS`가 아니다
- [ ] `fail` 항목은 전부 "어디서 무엇이 문제인지" 구체적 위치와 함께 기록된다 (막연한 "문제 있음"이 아니다)
- [ ] 출처 대장에 AI 생성 이미지·영상·오디오가 하나도 섞이지 않는다
- [ ] 출처 정보가 불완전한 항목은 조용히 누락되지 않고 별도 목록으로 남는다
- [ ] 같은 입력으로 다시 실행해도 동일한 결과가 나온다 (재현성)
- [ ] **(중요) 다른 유적지의 산출물로 실행해도 위 기준을 동일하게 만족한다**
